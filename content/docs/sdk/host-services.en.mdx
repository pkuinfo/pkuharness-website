---
title: HostServices
description: Signatures and behaviour of every host service a bundled plugin gets as ctx.services or props.services, plus the job, widget catalog and ongoing-notification types.
---

A plugin can't call the app's internal code. When it needs to open a browser, pick a file, send a
campus request or create a reminder, it calls a service that the host provides. Tools get these
services as `ctx.services`, and screens and widgets get them as `props.services`. This page lists
the signature and behaviour of each service.

Source: `packages/sdk/src/plugin.ts`. Concepts: [Host services](/en/docs/concepts/host-services).

```ts
interface HostServices {

  files: {

  remote: {
    install(input: { url: string; name?: string; token?: string }): Promise<{ id: string; name: string; tools: { name: string; effect: ToolEffect }[] }>;

  genui: {
    describeCatalog(): string;

  };
  notify: {
    readiness(): Promise<NotifyReadiness>;

  };
  sms: {

  };
  scheduler: {
    create(input: JobInput): Promise<Job>;
    update(id: string, patch: JobPatch): Promise<Job>;
    remove(id: string): Promise<void>;
    get(id: string): Job | undefined;
    list(): Job[];
    runCheck(id: string): Promise<CheckResult>;
  };
  widgets: {
    list(): Widget[];
    get(id: string): Widget | undefined;
    newId(): string;
    put(widget: Widget): Promise<void>;
    remove(id: string): Promise<void>;
    reorder(ids: string[]): Promise<void>;
    preview(widget: Widget): Promise<Record<string, unknown>>;
    resolve(widget: Widget, force?: boolean): Promise<Record<string, unknown>>;
    catalog(): WidgetCatalogEntry[];
  };
  todos: {
    list(): Todo[];
    get(id: string): Todo | undefined;

```

## Behaviour notes

The notes below describe how each member behaves and what to watch for when you call it.

- **`browser.open`** opens the page in a system browser tab (Custom Tabs on Android,
  SFSafariViewController on iOS). App links on that page (`weixin://`, `alipays://`) open those
  apps, so a checkout page can lead on to WeChat Pay or Alipay. The call resolves as soon as the page
  is open, so it can't tell you whether a payment went through. When the user comes back to the app,
  read the result again, for example the balance.
- **`files.pick`** can only be used by the user. Call it from a screen in response to a tap, never
  from an agent tool. `types` are MIME types and may use wildcards, as in
  `['application/pdf', 'image/*']`. It resolves to `[]` if the user cancels. The picked files are
  copied into the app cache, and you get references to them (URIs valid for this app session), not
  their bytes.
- **`crypto.sha256`** returns the SHA-256 of the UTF-8 text as lowercase hex. Plugins have no crypto
  library of their own, so use it for request signatures.
- **`registry`** is a read-only view of the installed plugins and tools. `tool(id)` also resolves
  legacy ids.
- **`docs`** manages document (`PLUGIN.md`) plugins and is used by the `plugins` plugin. `review`
  opens the app's permission sheet for a link or a set of files and resolves once the sheet is
  shown; the user then decides in the sheet. `source(id)` returns an installed document plugin's
  files, so you can read or fork it, and returns `null` for any other plugin. This member is
  optional, so check that it exists before you use it.
- **`remote`** installs and removes remote plugins, which connect through the Model Context
  Protocol (MCP). It is used by the `plugins` plugin.
- **`genui`**: `describeCatalog()` returns the component catalog as text that you can put in a tool
  description. `checkSpec(spec)` validates a spec against that catalog.
- **`notify.readiness` / `fix`**: `readiness` tells you whether reminders can fire on time. It
  checks the notification permission, exact alarms and battery optimisation. Call `fix` only from a
  tap. A system settings screen may return before the user changes anything, so read `readiness`
  again when the app comes back to the foreground.
- **`sms.awaitCode`** resolves with the code from the next incoming SMS once the user allows the app
  to read that one message (Android SMS User Consent). It returns `null` when the feature is
  unavailable, when the user denies it, when no code can be found, or after 5 minutes. Call it right
  after you ask the service to send the SMS.
- **`scheduler`**: `Trigger`, `Action` and `Job` are defined on the
  [scheduler](/en/docs/sdk/scheduler) page. `runCheck` runs a check job immediately.
- **`widgets.preview` / `resolve`** fill in a widget's bindings and return the state its spec will
  see. `preview` always fetches fresh data. `resolve` uses a cache whose entries expire after their
  time to live (TTL), unless you pass `force`.
- **`widgets.catalog`** lists the native widgets contributed by enabled plugins.
- **`todos`**: the `source` argument records who made the change.
- **`campus.request`** needs the `campus-session` capability. See [campus](/en/docs/sdk/campus).
- **`campus.otp`** returns the current 手机令牌 (mobile authenticator) code if the user has bound the
  app's built-in authenticator, and `null` otherwise. A plugin never gets the secret itself.
- **`campus.otpStatus`, `otpBindStart`, `otpBindFinish`, `otpUnbindLocal`** manage the
  authenticator. Only the screens of the bundled authenticator plugin should call them.
- **`campus.openSignedIn`** opens the service in the system browser, already signed in through the
  service's own sign-in hand-off. The host builds the URL, so the plugin never sees the session
  token. It rejects if the service has no such hand-off.
- **`ongoing`** exists only when the device has the `ongoing` capability (Android). Start it from a
  user action and stop it when you're done.
- **`timetable.reloadSemester`** makes the host read the semester again after the calendar plugin
  has saved it.

## Types used above

These types appear in the signatures above and are not defined on other pages.

```ts
type JobInput = { title: string; trigger: Trigger; action: Action; source: JobSource; enabled?: boolean; meta?: Record<string, unknown> };
type JobPatch = Partial<Pick<Job, 'title' | 'trigger' | 'action' | 'enabled' | 'meta'>>;
type CheckResult = { notified: boolean; value?: unknown; error?: string };

type ToolInfo = { id: string; pluginId: string; title: string; effect: ToolEffect };

type PluginInfo = {
  id: string;
  name: string;
  kind: 'system' | 'builtin' | 'remote';
  enabled: boolean;
  modes: Record<ToolEffect, 'auto' | 'ask' | 'off'>;
  tools: { id: string; title: string; effect: ToolEffect }[];
};

interface WidgetCatalogEntry {
  plugin: string;
  pluginName: string;
  widget: string;
  title: string;
  description: string;
  sizes: WidgetSize[];
  defaultSize: WidgetSize;
  /** JSON Schema of the widget's config, if it takes any. */
  config?: Record<string, unknown>;
}

interface OngoingOptions {
  title: string;
  body?: string;
  /** When the activity ends (ms epoch): shown as a countdown; the host stops it then. */
  until?: number;
  /** Label of the notification's stop action (default 停止). */
  stopLabel?: string;
  /** Called when the user taps stop (or the system ends the service). */
  onStop?: () => void;
}

interface OngoingHandle {
  update(p: { title?: string; body?: string }): void;
  stop(): void;
}
```

## Example: pick a file and upload it

```ts
import type { HostServices } from '@pku-harness/sdk';

/** Call from a screen's button handler: only the user can pick files. */
export async function pickAndSubmit(services: HostServices, hiddenFields: [string, string][]) {
  const [file] = await services.files.pick({ types: ['application/pdf'] });
  if (!file) return null; // cancelled
  return services.campus.request('blackboard', {
    url: '/webapps/assignment/uploadAssignment?action=submit',
    method: 'POST',
    multipart: {
      fields: hiddenFields, // the submission form's hidden fields (nonce, course_id, content_id…)
      files: [{ field: 'newFile_LocalFile0', name: file.name, mime: file.mime, uri: file.uri }],
    },
  });
}
```

This is a shortened version of how the `courses` plugin submits an assignment. The real flow is
`submitAssignment` in `plugins/courses/src/api.ts`, ported from pkucli's `crates/course`. It first
reads the submission form to get its hidden fields and a fresh nonce, then posts the submission,
and finally reads the assignment page again to confirm the new attempt. The file bytes never pass
through the plugin. The host streams them directly from the picked file's URI.
