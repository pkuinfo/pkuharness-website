`@pku-harness/sdk` is the only package a bundled plugin depends on (besides `zod`, `react` and
`react-native`). It is TypeScript source in the plugins repository; the app's bundler (Metro) compiles it like app code.
Peer dependencies: `zod ^4`, `react >=19`.

## Install

There is no npm package. The SDK lives in
[`pku-harness-plugins`](https://github.com/pkuinfo/pku-harness-plugins) (`packages/sdk`), and you
work inside a checkout of that repository: its bun workspace and `tsconfig.json` resolve
`@pku-harness/sdk` to `packages/sdk/src`.

```bash
git clone https://github.com/pkuinfo/pku-harness-plugins.git
cd pku-harness-plugins
bun install
```

The app includes the same repository as its git submodule `plugins/`, so a plugin you build there
runs in the app ([Bundled plugin → Run it in the app](/docs/build/bundled-plugin#run-it-in-the-app)).

```ts
import { definePlugin, defineTool, type PluginScreenProps } from '@pku-harness/sdk';
```

Everything is exported from the package root.

## Conventions

- Times are **epoch milliseconds**, device-local when interpreted as wall time. Model- and
  form-facing strings use local `"YYYY-MM-DD HH:mm"`.
- Timetable weekdays use JavaScript numbering (0 = Sunday … 6 = Saturday); `weekdayName` takes
  1 = Monday … 7 = Sunday.
- Schemas are zod 4 objects; types are `z.infer` of them.
- Pure helpers have no React Native imports and are unit-tested with `bun test`.
