The [marketplace](/en/marketplace) lists every PKU Harness plugin: the official ones, and
community plugins written as a `PLUGIN.md` folder (which the app interprets) or served as remote
MCP servers. Like [skills.sh](https://skills.sh), it is **indexed from GitHub repositories**. You
don't upload a package; you point the marketplace at a public repo and it finds every plugin in
it.

## How listing works

<Steps>
<Step>

**Write a `PLUGIN.md` for each plugin.** One folder per plugin, at any depth. The YAML
frontmatter declares what the plugin is and what it may touch, the Markdown body tells the agent
how to use it, and the tools live in `tools/*.yaml`. A repo can hold one plugin or a hundred. See
the [manifest reference](/en/docs/marketplace/manifest). (A remote MCP server can still be
described with a `pku-harness.plugin.json` until `remote.mcp` in `PLUGIN.md` replaces it.)

</Step>
<Step>

**Check and submit the repo.** Paste the repo into [/marketplace/submit](/en/marketplace/submit).
The site scans it live and shows every plugin it found, with errors, warnings and a preview of its
card. **Submit for listing** opens a prefilled GitHub issue; a bot scans the repo again and opens
a pull request that adds it to `data/sources.json`, and a maintainer merges it.

</Step>
<Step>

**Push to update.** The marketplace rescans every listed repo about once an hour. Edit a
manifest, add a plugin folder or delete one, and the listing follows. There's nothing to
resubmit.

</Step>
</Steps>

## Handles and ids

A plugin's **handle** is `owner/repo/path`, the folder that holds its `PLUGIN.md`, for example
`alice/campus-tools/canteen`. Its page on this site uses the id instead:
`/marketplace/alice/campus-tools/canteen-menu`. The `id` must be **unique across the whole
marketplace**, because the app registers tools as `<id>.<tool>` (and remote plugins as the MCP
server `mcp-<id>`). Two plugins with the same id would collide on a phone. The repo that was
listed first keeps the id, and official ids are reserved.

## Official, verified and community

| Badge | Meaning |
|---|---|
| **官方 Official** | Maintained by pkuinfo in [`pku-harness-plugins`](https://github.com/pkuinfo/pku-harness-plugins) and listed from its `registry/registry.json`. |
| **已审核 Verified** | A community plugin whose source a maintainer has read. Recorded per plugin id in `data/sources.json`. |
| **社区 Community** | Listed automatically after passing the scanner's checks. Nobody has read the source yet. |

Unverified plugins work exactly the same. The badge only tells students how much review a plugin
has had. The [review policy](/en/docs/marketplace/review) explains what gets a plugin verified or
removed.

## How the app installs a plugin

- **Declarative** plugins (`PLUGIN.md`) are installed **by link**. The plugin page has an
  *Open in app* button (`pkuharness://plugin?src=…`), a QR code, and the install link (the GitHub
  folder URL) to paste into 设置 → 插件. The app fetches the files, shows the review sheet
  (Official or Community, campus services, websites, app features, and each tool with its
  effect) and stores the plugin on the phone. Later it re-fetches the link: an update that asks
  for nothing new applies silently, and one that asks for more waits for the user.
- **Built-in** plugins ship with the app; users turn them on in 设置 → 插件. The official plugin
  documents among them update from their GitHub link like any other document.
- **Remote** plugins are MCP servers (Streamable HTTP). Users add them from 设置 → 插件 → 插件市场,
  or paste the endpoint URL by hand. The app connects to the endpoint and registers its tools as
  `mcp-<id>`. With `"auth": "bearer"`, the user pastes a token, which stays in the phone's
  keychain.
- **Self-hosted** plugins (no `endpoint`) are listed with their source. Users deploy their own
  instance and paste its URL.

No third-party code runs on the phone. The app interprets the steps a `PLUGIN.md` declares, and a
remote plugin runs on its author's server. The app makes campus requests itself, with the user's
session, so plugins never see passwords, cookies or tokens.

## For the app and for agents

| URL | What |
|---|---|
| [`/marketplace.json`](/marketplace.json) | The full index (`MarketplaceIndex`: `plugins[]` + `sources[]`), CORS-enabled, refreshed hourly. |
| [`/marketplace/llms.txt`](/marketplace/llms.txt) | The same list as Markdown, for language models. |
| [`/schema/plugin-manifest.v1.json`](/schema/plugin-manifest.v1.json) | JSON Schema of `pku-harness.plugin.json` (the remote MCP fallback). |
| `POST /api/marketplace/scan` | `{ "repo": "owner/repo" }` → a scan report (rate limited; the submit page uses it). |
