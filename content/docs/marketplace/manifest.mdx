一个插件就是一个**带 `PLUGIN.md` 的文件夹**。YAML frontmatter 是清单，Markdown 正文是给助手的使用说明。完整的语言规范（工具、步骤、表达式、界面）见 [`docs/PLUGIN-LANGUAGE.md`](https://github.com/pkuinfo/pku-harness/blob/master/docs/PLUGIN-LANGUAGE.md)。本页只讲插件市场会读取和检查的部分。入门介绍请看[声明式插件](/docs/build/declarative-plugins)。

```md title="campus-tools/canteen/PLUGIN.md"
---
spec: 1
id: canteen-menu
name: 食堂菜单
description: 今天各食堂的菜单和营业时间。
version: 1.0.0
author: alice
icon: food
network: [dining.pku.edu.cn]
tools:
  menu: tools/menu.yaml
widgets:
  today: widgets/today.json
dataSources:
  today: { tool: menu, args: { day: today }, ttl: 30m }
i18n:
  en: { name: Canteen menu, description: "Today's menus and opening hours." }
---

Use `menu` when the user asks what to eat or which canteen is open. Prices are in yuan.
```

## 扫描器去哪里找 [#where-the-scanner-looks]

扫描器通过 GitHub API 读取仓库的默认分支：

1. 如果仓库根目录有 **`pku-harness.json`**，扫描器只检查其中列出的文件夹（最多 200 个），并按列出的顺序。大型 monorepo 适合这样做：

   ```json title="pku-harness.json"
   { "plugins": ["plugins/canteen", "plugins/library-seat"] }
   ```

   `"."` 表示仓库根目录。列出的文件夹里没有清单会报错。

2. 否则，任意层级的每个 **`PLUGIN.md`** 都算一个插件。名为 `node_modules` 或以 `.` 开头的文件夹会被跳过。

一个文件夹只对应一个插件。如果一个文件夹里有多份清单，**`PLUGIN.md` 优先**，其次是 `pku-harness.plugin.json`，最后是带 `"pkuHarness"` 对象的 `package.json`（见[远程 MCP 插件](#remote-mcp-plugins)）。

提交时也可以指向一个子文件夹（`https://github.com/owner/repo/tree/main/plugins`），这样只扫描那个文件夹。

## Frontmatter [#frontmatter]

| 字段 | 必填 | 说明 |
|---|---|---|
| `spec` | 是 | `1`。App 会拒绝它不认识的版本。 |
| `id` | 是 | `^[a-z0-9][a-z0-9-]{1,40}$`。在整个插件市场里唯一，因为工具会注册为 `<id>.<tool>`。 |
| `name` | 是 | 显示名称，中文优先。 |
| `description` | 是 | 一句话，4–200 个字符。 |
| `version` | 是 | 语义化版本号。如果 YAML 会把它读成数字就加引号（`"1.0"` 本来也不是合法的 semver）。 |
| `author` | 是 | GitHub 用户名或名字。 |
| `icon`、`homepage` | | 宿主图标集里的图标名；一个 URL。 |
| `minApp` | | 插件需要的最低 App 版本（`x.y.z`）。 |
| `campus` | | **带着用户会话**调用的校园服务：`card`、`its`、`treehole`、`blackboard`、`elective`、`cwfw`、`cwpay`、`bdkj`、`library`、`library-space`、`portal`…… |
| `network` | | 会访问的公开主机（`dining.pku.edu.cn`、`*.example.com`），只允许 HTTPS。 |
| `abilities` | | 宿主能力：`verify`、`otp`、`todos`、`timetable`、`scheduler`、`browser`、`campusPage`、`sms`、`files`、`crypto`、`cloud`（[操作与效果](/docs/build/declarative-plugins#host-abilities)）。写别的名字会报错（App 会拒绝）。 |
| `shared` | | 一个 YAML 文件（`shared.yaml`），里面的 `constants` 和 `functions` 所有工具都能用。 |
| `tools` | | 工具名 → 文件（`tools/menu.yaml`）或内联工具的映射。每个工具都有 `title`、`description` 和如实填写的 `effect`：`read`、`write`、`money` 或 `public`。 |
| `dataSources` | | 供小组件和定时检查轮询的读取工具：`{ tool, args?, ttl }`。 |
| `widgets`、`screens` | | 名称 → JSON 文件的映射（生成式界面 spec + 数据绑定）。 |
| `settings`、`commands`、`defaultModes` | | 设置项、斜杠命令、按效果建议的授权方式。 |
| `requires` | | 可以不写，因为它会从各项声明中**推导**出来（见下文）。 |
| `cloud` | | 使用 PKU Harness Cloud，并附上大白话的数据说明（[见下文](#cloud-disclosure)）。 |
| `server` | | 服务端函数（[CLOUD-FUNCTIONS.md](https://github.com/pkuinfo/pku-harness/blob/master/docs/CLOUD-FUNCTIONS.md)）。需要 `cloud.disclosure`，隐含 `cloud.uses: [functions]`。**官方服务器暂不开启**：请让插件在手机端完成工作，或使用你自己的后端。 |
| `i18n.en` | | 英文的 `name`、`description` 及其他覆盖字符串。 |
| `remote` | | `{ mcp: https URL, auth?: none \| bearer }`，把这个文件夹变成[远程 MCP 插件](#remote-mcp-plugins)。 |

**Markdown 正文**会成为插件给模型的使用说明。插件市场会在插件页上展示它（超过 20,000 个字符的部分会被截掉），超过 8,000 个字符时给出警告，因为每次对话都会带上它。只写清楚什么时候用哪个工具、数字代表什么就够了。

### 文件 [#files]

App 加载的每个文件都必须在 frontmatter 里点名（`tools`、`shared`、`widgets`、`screens`），App 从不遍历文件夹。扫描器会检查每个路径：

- 相对于 `PLUGIN.md`，不含 `..`、不以 `/` 开头、没有 URL 协议；
- 在仓库里确实存在（文件缺失是**错误**）；
- 连同 `PLUGIN.md` 总共不超过 **512 KB**（按 GitHub 文件树里的 blob 大小计算）。

扫描器还会下载每个被点名的工具文件，读出它的 `title` 和 `effect`，插件页会把它们作为权限面板的一部分展示出来。`tests/`、`README.md` 和 `assets/` 会被忽略。

### 推导出的能力需求 [#derived-capabilities]

插件页和筛选器里显示的 `requires`，是你写的内容加上各项声明隐含的内容：

| 声明 | 隐含 |
|---|---|
| 任何 `campus` 服务 | `campus-session`、`network` |
| `campus: [cwfw]` | 另加 `campus-network`（cwfw 只在校园网内响应） |
| `network` 主机，或 `remote` | `network` |
| `abilities: [scheduler]` | `background` |
| `cloud.uses` 非空，或有 `server` | `cloud` |

### 安装链接 [#install-links]

每个 `PLUGIN.md` 插件的页面都会显示它的安装链接（默认分支上的 GitHub 文件夹 URL，比如 `https://github.com/alice/campus-tools/tree/main/canteen`）、一个*在 App 中打开*按钮（深链接为 `pkuharness://plugin?src=<url-encoded install link>`），以及这个深链接的二维码。页面上显示的标识是 `owner/repo/path`。

## 远程 MCP 插件 [#remote-mcp-plugins]

远程插件跑在你自己的服务器上，通过 Streamable HTTP 提供 MCP 服务。App 把它当作 MCP 服务器 `mcp-<id>` 来连接，所以请把服务器的 `name` 设成插件的 `id`。用一个只有 `remote`、没有工具的 `PLUGIN.md` 来描述它（在这里声明的工具会被忽略，并给出警告）：

```md title="PLUGIN.md"
---
spec: 1
id: canteen-live
name: 食堂实时人数
description: 各食堂当前排队人数。
version: 1.0.0
author: alice
remote: { mcp: "https://canteen.example.com/mcp", auth: none }
---

Use the tools when the user asks how crowded a canteen is.
```

远程服务器永远拿不到校园会话，所以远程插件写了 `campus` 会得到警告。

### 兼容方案：`pku-harness.plugin.json` [#fallback-pku-harnesspluginjson]

在 `PLUGIN.md` 的 `remote.mcp` 取代它之前，插件市场仍然会为远程 MCP 服务器读取 `pku-harness.plugin.json`（以及 `package.json` 里的 `"pkuHarness"`）。把 `$schema` 指向 [`/schema/plugin-manifest.v1.json`](/schema/plugin-manifest.v1.json)，编辑器就能边写边校验。

```json title="pku-harness.plugin.json"
{
  "$schema": "https://<this site>/schema/plugin-manifest.v1.json",
  "id": "canteen-live",
  "name": "食堂实时人数",
  "description": "各食堂当前排队人数。",
  "endpoint": "https://canteen.example.com/mcp",
  "requires": ["network"],
  "scopes": ["dining.pku.edu.cn"]
}
```

### `pku-harness.plugin.json` 字段 [#pku-harnesspluginjson-fields]

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | `^[a-z0-9][a-z0-9-]{1,40}$`，在整个插件市场里唯一。**请把它用作 MCP 服务器的 `name`**：App 把插件安装为 `mcp-<id>`，并据此判断它是否已安装。 |
| `name` | string | 是 | 显示名称，中文优先（不超过 40 个字符）。 |
| `description` | string | 是 | 一句话，4–200 个字符，说明它能帮同学做什么。 |
| `author` | string | | 默认是仓库的 GitHub 所有者。 |
| `kind` | `"remote"` \| `"builtin"` | | 默认 `"remote"`。`"builtin"` 保留给随 App 内置的插件。 |
| `endpoint` | https URL \| null | | 公开的 MCP 端点（Streamable HTTP）。**自建**插件省略或填 `null`。必须是 `https://`、公网主机，不能带凭据或查询字符串。 |
| `auth` | `"none"` \| `"bearer"` | | 默认 `"none"`。`"bearer"` 表示用户要在 App 里粘贴一个 token。 |
| `icon` | string | | App 图标集里的图标名（`wallet`、`food`、`library`、`bus`……），或指向方形图片的 `https://` URL。 |
| `requires` | capability[] | | 插件需要什么，见下文。 |
| `scopes` | string[] | | 插件会访问的主机名（`"dining.pku.edu.cn"`、`"*.example.com"`），会展示给用户。 |
| `tags` | string[] | | 小写的搜索标签。 |
| `cloud` | object | | PKU Harness Cloud 的使用声明，从 `PluginDef.cloud` 复制过来，见下文。 |
| `version` | string | | 显示在插件页上。 |
| `license` | string | | SPDX 标识，比如 `"MIT"`。 |
| `homepage` | https URL | | 文档或项目主页。 |
| `i18n.en` | `{ name?, description? }` | | 英文字符串。 |
| `$schema` | string | | 扫描器会忽略它。 |

未知字段会被忽略并给出警告，免得拼写错误让数据悄悄丢失。

#### 写在 package.json 里 [#in-packagejson]

```json title="package.json"
{
  "name": "@campus-tools/library-seat",
  "version": "0.3.0",
  "description": "图书馆座位查询与预约提醒。",
  "license": "MIT",
  "pkuHarness": {
    "id": "library-seat",
    "name": "图书馆座位",
    "endpoint": "https://seat.example.com/mcp",
    "requires": ["network"],
    "scopes": ["seat.lib.pku.edu.cn"]
  }
}
```

`description`、`version`、`license` 和 `homepage` 默认取 package 自身的字段，`pkuHarness` 里写了的会覆盖它们。**没有 `id`** 的 `pkuHarness` 对象被视为 SDK 元数据（内置插件用的是 `{ "builtin": true }`），不会上架。

## 能力需求（`requires`） [#capabilities-requires]

| 值 | 展示给用户的含义 |
|---|---|
| `network` | 会访问互联网上的服务器。 |
| `campus-network` | 部分主机只在北大校园网内响应。 |
| `campus-session` | 使用用户已登录的校园会话办事。`PLUGIN.md` 插件通过声明 `campus` 获得它（由 App 签发请求）；远程 MCP 服务器永远拿不到，所以扫描器会警告。 |
| `notifications` | 发送本地通知。 |
| `background` | App 关闭时也会运行定时检查。 |
| `shell`、`filesystem` | 手机两者都没有，App 会隐藏需要它们的插件。会给出警告。 |
| `cloud` | 使用 PKU Harness Cloud，必须有 `cloud` 块。 |
| `ongoing` | 显示一个实时的持续活动。 |

远程插件跑在你的服务器上，所以只声明需要**手机**提供的东西。

## 云服务数据说明 [#cloud-disclosure]

```json
"cloud": {
  "uses": ["store"],
  "e2e": true,
  "disclosure": { "zh": ["你的收藏列表会加密存到云端，用于多设备同步。"], "en": ["Your favourites are stored encrypted in the cloud to sync devices."] }
}
```

规则与注册表里的 `cloudIssues()` 相同：

- `uses` 不能有重复项；
- `uses` 非空时，至少要有一行 `disclosure.zh`，用大白话说明哪些数据会离开设备；
- 不能有空行；
- 如果写了 `disclosure.en`，必须逐行翻译 `zh`；
- 外部 `backend.url` 必须是 `https`。

## 扫描器检查什么 [#what-the-scanner-checks]

有错误的插件不会上架。警告会显示在插件页的**检查结果**里。

| 检查项 | 级别 |
|---|---|
| 没有 frontmatter、YAML 或 JSON 不合法、违反 schema（`spec`、semver 格式的 `version` 等） | 错误 |
| 仓库内 `id` 重复、占用官方 id，或 id 已被另一个已上架仓库使用 | 错误 |
| 点名的文件是绝对路径、含 `..` 或不存在；总大小超过 512 KB | 错误 |
| 工具文件缺少 `title`、`description` 或合法的 `effect` | 错误 |
| `dataSources` 指向未声明的工具，`settings` 指向未声明的页面 | 错误 |
| `network` 里有不是主机名的条目 | 错误 |
| 端点（`remote.mcp`、`endpoint`）不是 https、是私有或本地主机或 IP、带凭据或查询字符串 | 错误 |
| 违反上面的 `cloud` 数据说明规则；有 `server` 但没有 `cloud.disclosure.zh` | 错误 |
| 未知的 `abilities` | 错误 |
| `PLUGIN.md` 里有未知的顶层字段（App 严格解析） | 错误 |
| 在 `pkuinfo/pku-harness-plugins` 之外使用 `kind: "builtin"`（JSON） | 错误 |
| 未知的 `campus` 服务 | 警告 |
| 有 `server`（官方服务器暂不开启）；写了 `abilities: [cloud]` 却没有 `cloud` 或 `server` 块 | 警告 |
| 远程插件写了 `campus`（JSON 清单写了 `campus-session`） | 警告 |
| `requires` 里有 `shell`、`filesystem` | 警告 |
| `requires: cloud` 但没有 `cloud` 块 | 警告 |
| Markdown 正文为空或太长；没有任何工具、命令或小组件 | 警告 |
| 远程插件声明了 `tools`（会被忽略） | 警告 |
| JSON 清单里有未知字段 | 警告 |
| 没有 `i18n.en`；JSON：没有 `endpoint`（自建）、没有 `license` | 提示 |

限制：每个仓库最多 100 个插件、300 个 `package.json`；每个插件最多 40 个工具文件（每个仓库最多 400 个）；每个下载的文件最大 256 KB；每次 GitHub 请求最长 10 秒。仓库太大、GitHub 一次列不完文件树时会给出警告，加一个 `pku-harness.json` 就能解决。
