A plugin is a **folder with a `PLUGIN.md`**. Its YAML frontmatter is the manifest; its Markdown
body is the instructions the agent gets. The full language (tools, steps, expressions, UI) is
specified in
[`docs/PLUGIN-LANGUAGE.md`](https://github.com/pkuinfo/pku-harness/blob/master/docs/PLUGIN-LANGUAGE.md);
this page covers what the marketplace reads and checks. For an introduction, see
[Declarative plugins](/docs/build/declarative-plugins).

```md title="campus-tools/canteen/PLUGIN.md"
---
spec: 1
id: canteen-menu
name: 食堂菜单
description: 今天各食堂的菜单和营业时间。
version: 1.0.0
author: alice
icon: food
network: [dining.pku.edu.cn]
tools:
  menu: tools/menu.yaml
widgets:
  today: widgets/today.json
dataSources:
  today: { tool: menu, args: { day: today }, ttl: 30m }
i18n:
  en: { name: Canteen menu, description: "Today's menus and opening hours." }
---

Use `menu` when the user asks what to eat or which canteen is open. Prices are in yuan.
```

## Where the scanner looks

The scanner reads the repository's default branch through the GitHub API:

1. If the repo root has a **`pku-harness.json`**, only the folders it lists are checked, in that
   order. Use this in large monorepos:

   ```json title="pku-harness.json"
   { "plugins": ["plugins/canteen", "plugins/library-seat"] }
   ```

   `"."` means the repo root. A listed folder without a manifest is an error.

2. Otherwise every **`PLUGIN.md`** at any depth is a plugin. Folders named `node_modules` or
   starting with `.` are skipped.

One plugin per folder. If a folder has more than one manifest, **`PLUGIN.md` wins**, then
`pku-harness.plugin.json`, then a `package.json` with a `"pkuHarness"` object (see
[remote MCP plugins](#remote-mcp-plugins)).

A submission can also point at a sub-folder (`https://github.com/owner/repo/tree/main/plugins`);
then only that folder is scanned.

## Frontmatter

| Field | Required | Notes |
|---|---|---|
| `spec` | yes | `1`. The app refuses versions it doesn't know. |
| `id` | yes | `^[a-z0-9][a-z0-9-]{1,40}$`. Unique across the marketplace: tools are registered as `<id>.<tool>`. |
| `name` | yes | Display name, Chinese first. |
| `description` | yes | One sentence, 4–200 characters. |
| `version` | yes | Semver. Quote it if YAML would read a number (`"1.0"` is not semver anyway). |
| `author` | yes | GitHub handle or name. |
| `icon`, `homepage` | | Icon from the harness set; a URL. |
| `campus` | | Campus services called **with the user's session**: `card`, `its`, `treehole`, `blackboard`, `elective`, `cwfw`, `cwpay`, `bdkj`, `library`, `library-space`, `portal`, … |
| `network` | | Public hosts it calls (`dining.pku.edu.cn`, `*.example.com`). HTTPS only. |
| `abilities` | | Host abilities: `verify`, `otp`, `todos`, `timetable`, `scheduler`, `browser`, `campusPage`, `sms`, `files`, `crypto`. Any other name is an error (the app refuses it). |
| `tools` | | Map of tool name → file (`tools/menu.yaml`) or an inline tool. Every tool has `title`, `description` and an honest `effect`: `read`, `write`, `money` or `public`. |
| `dataSources` | | Read tools that widgets and scheduled checks poll: `{ tool, args?, ttl }`. |
| `widgets`, `screens` | | Map of name → JSON file (generative-UI spec + bindings). |
| `settings`, `commands`, `defaultModes` | | Settings rows, slash commands, suggested per-effect permission modes. |
| `requires` | | Optional: it is **derived** from the declarations (below). |
| `cloud` | | PKU Harness Cloud use with a plain-language disclosure ([below](#cloud-disclosure)). |
| `i18n.en` | | English `name`, `description` and other overlay strings. |
| `remote` | | `{ mcp: https URL, auth?: none \| bearer }` turns the folder into a [remote MCP plugin](#remote-mcp-plugins). |

The **Markdown body** becomes the plugin's instructions for the model. The marketplace shows it
on the plugin page (capped at 20,000 characters) and warns above 8,000: it is sent with every
prompt, so keep it to when to use which tool and what the numbers mean.

### Files

Every file the app loads is named in the frontmatter (`tools`, `widgets`, `screens`); the app
never lists folders. The scanner checks that each path:

- is relative to `PLUGIN.md`, with no `..`, no leading `/` and no URL scheme;
- exists in the repository (a missing file is an **error**);
- together with `PLUGIN.md` stays within **512 KB** (from the GitHub tree's blob sizes).

It also downloads each named tool file to read its `title` and `effect`, which the plugin page
shows as part of the permission sheet. `tests/`, `README.md` and `assets/` are ignored.

### Derived capabilities

The plugin page and the filters show `requires` as the union of what you list and what the
declarations imply:

| Declaration | Implies |
|---|---|
| any `campus` service | `campus-session`, `network` |
| `campus: [cwfw]` | also `campus-network` (cwfw only answers on the campus network) |
| `network` hosts, or `remote` | `network` |
| `abilities: [scheduler]` | `background` |
| `abilities: [scheduler]` | `background` |
| `cloud.uses` not empty | `cloud` |

### Install links

Each `PLUGIN.md` plugin's page shows its install link (the GitHub folder URL on the default
branch, e.g. `https://github.com/alice/campus-tools/tree/main/canteen`), an *Open in app* button
with the deep link `pkuharness://plugin?src=<url-encoded install link>`, and a QR code of that deep
link. The handle shown is `owner/repo/path`.

## Remote MCP plugins

A remote plugin runs on your server and speaks MCP over Streamable HTTP. The app connects to it
as the MCP server `mcp-<id>`, so use the `id` as your server's `name`. Describe it with a
`PLUGIN.md` that has `remote` and no tools:

```md title="PLUGIN.md"
---
spec: 1
id: canteen-live
name: 食堂实时人数
description: 各食堂当前排队人数。
version: 1.0.0
author: alice
remote: { mcp: "https://canteen.example.com/mcp", auth: none }
---

Use the tools when the user asks how crowded a canteen is.
```

Remote servers never receive campus sessions, so `campus` on a remote plugin is a warning.

### Fallback: `pku-harness.plugin.json`

Until `remote.mcp` in `PLUGIN.md` replaces it, the marketplace still reads
`pku-harness.plugin.json` (and `package.json` → `"pkuHarness"`) for remote MCP servers. Point
`$schema` at [`/schema/plugin-manifest.v1.json`](/schema/plugin-manifest.v1.json) and editors
validate it as you type.

```json title="pku-harness.plugin.json"
{
  "$schema": "https://<this site>/schema/plugin-manifest.v1.json",
  "id": "canteen-live",
  "name": "食堂实时人数",
  "description": "各食堂当前排队人数。",
  "endpoint": "https://canteen.example.com/mcp",
  "requires": ["network"],
  "scopes": ["dining.pku.edu.cn"]
}
```

### `pku-harness.plugin.json` fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string | yes | `^[a-z0-9][a-z0-9-]{1,40}$`. Unique across the marketplace. **Use it as your MCP server `name`**: the app installs the plugin as `mcp-<id>` and uses that to show it as installed. |
| `name` | string | yes | Display name, Chinese first (≤ 40 chars). |
| `description` | string | yes | One sentence, 4–200 chars, saying what it does for students. |
| `author` | string | | Defaults to the GitHub owner of the repo. |
| `kind` | `"remote"` \| `"builtin"` | | Defaults to `"remote"`. `"builtin"` is reserved for plugins bundled in the app. |
| `endpoint` | https URL \| null | | Public MCP endpoint (Streamable HTTP). Omit or `null` for **self-hosted** plugins. Must be `https://`, a public host, no credentials or query string. |
| `auth` | `"none"` \| `"bearer"` | | Defaults to `"none"`. `"bearer"`: users paste a token in the app. |
| `icon` | string | | An icon name from the app's set (`wallet`, `food`, `library`, `bus`, …) or an `https://` URL to a square image. |
| `requires` | capability[] | | What the plugin needs. See below. |
| `scopes` | string[] | | Host names the plugin talks to (`"dining.pku.edu.cn"`, `"*.example.com"`). Shown to users. |
| `tags` | string[] | | Lowercase search tags. |
| `cloud` | object | | PKU Harness Cloud use, copied from `PluginDef.cloud`. See below. |
| `version` | string | | Shown on the plugin page. |
| `license` | string | | SPDX id, e.g. `"MIT"`. |
| `homepage` | https URL | | Docs or project page. |
| `i18n.en` | `{ name?, description? }` | | English strings. |
| `$schema` | string | | Ignored by the scanner. |

Unknown fields are ignored with a warning (so a typo doesn't silently drop data).

#### In package.json

```json title="package.json"
{
  "name": "@campus-tools/library-seat",
  "version": "0.3.0",
  "description": "图书馆座位查询与预约提醒。",
  "license": "MIT",
  "pkuHarness": {
    "id": "library-seat",
    "name": "图书馆座位",
    "endpoint": "https://seat.example.com/mcp",
    "requires": ["network"],
    "scopes": ["seat.lib.pku.edu.cn"]
  }
}
```

`description`, `version`, `license` and `homepage` default to the package's own fields; anything
inside `pkuHarness` overrides them. A `pkuHarness` object **without an `id`** is treated as SDK
metadata (the bundled plugins use `{ "builtin": true }`) and is not listed.

## Capabilities (`requires`)

| Value | Meaning shown to users |
|---|---|
| `network` | Talks to servers on the internet. |
| `campus-network` | Some hosts only answer on the PKU campus network. |
| `campus-session` | Acts with the user's logged-in campus session. `PLUGIN.md` plugins get it by declaring `campus` (the app signs the requests); remote MCP servers never do, so the scanner warns. |
| `notifications` | Sends local notifications. |
| `background` | Runs scheduled checks while the app is closed. |
| `shell`, `filesystem` | Phones have neither; the app hides plugins that need them. Warned. |
| `cloud` | Uses PKU Harness Cloud; requires a `cloud` block. |
| `ongoing` | Shows a live, ongoing activity. |

A remote plugin runs on your server, so only declare what the **phone** has to provide.

## Cloud disclosure

```json
"cloud": {
  "uses": ["store"],
  "e2e": true,
  "disclosure": { "zh": ["你的收藏列表会加密存到云端，用于多设备同步。"], "en": ["Your favourites are stored encrypted in the cloud to sync devices."] }
}
```

The same rules as `cloudIssues()` in the registry apply: no duplicate `uses`; non-empty `uses`
needs at least one `disclosure.zh` line saying in plain words what leaves the device; no empty
lines; `disclosure.en`, if present, translates every `zh` line; an external `backend.url` must be
`https`.

## What the scanner checks

Errors keep a plugin out of the marketplace; warnings are shown on its page under **Checks**.

| Check | Level |
|---|---|
| No frontmatter, invalid YAML or JSON, schema violations (`spec`, semver `version`, …) | error |
| Duplicate `id` in the repo, an official id, or an id another listed repo already uses | error |
| A named file that is absolute, contains `..`, or doesn't exist; total over 512 KB | error |
| A tool file without `title`, `description` or a valid `effect` | error |
| `dataSources` pointing at an undeclared tool, `settings` at an undeclared screen | error |
| `network` entries that aren't host names | error |
| Endpoint (`remote.mcp`, `endpoint`) not https, a private/local host or IP, credentials or a query string | error |
| `cloud` disclosure rules above | error |
| `kind: "builtin"` outside `pkuinfo/pku-harness-plugins` (JSON) | error |
| Unknown `campus` services or `abilities` | warning |
| `campus` on a remote plugin (`campus-session` on a JSON manifest) | warning |
| `shell`, `filesystem` in `requires` | warning |
| `requires: cloud` without a `cloud` block | warning |
| Empty or very long Markdown body; no tools, commands or widgets | warning |
| Unknown fields | warning |
| No `i18n.en`; JSON: no `endpoint` (self-hosted), no `license` | info |

Limits: 100 plugins and 300 `package.json` files per repo, 40 tool files per plugin, 256 KB per
downloaded file, 10 s per GitHub request. A repo too big for one GitHub tree call gets a warning;
add `pku-harness.json`.
