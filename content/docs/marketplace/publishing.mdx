## 提交之前 [#before-you-submit]

- 每个插件是一个带 `PLUGIN.md` 的文件夹，frontmatter 里点名的每个文件（`tools/`、`widgets/`、`screens/`）都已提交。见[清单参考](/docs/marketplace/manifest)和[声明式插件](/docs/build/declarative-plugins)。
- 如果是远程 MCP 插件：服务器已通过 HTTPS 部署（或者你写清楚了怎么自建），并且它的 `name` 等于 `id`。可以从 [`templates/remote-plugin`](https://github.com/pkuinfo/pku-harness-plugins/tree/main/templates/remote-plugin) 起步。
- 仓库在 github.com 上是**公开**的。
- 你遵守[审核规则](/docs/marketplace/review)：不碰校园密码、如实声明效果、返回数据而不是指令、写好云服务数据说明。

## 提交 [#submit]

1. 打开 [/marketplace/submit](/marketplace/submit)，粘贴 `owner/repo`、仓库 URL 或文件夹 URL（`https://github.com/owner/repo/tree/main/plugins`）。
2. 修好预览里显示的所有错误。每次 push 之后重新检查一遍（结果会缓存大约一分钟）。
3. 点击**提交上架**。它会在 [`pkuinfo/pkuharness-website`](https://github.com/pkuinfo/pkuharness-website/issues) 打开一个预填好的 issue，带 `plugin-submission` 标签。
4. GitHub Action 会再扫描一遍仓库，把报告评论到 issue 上。扫描通过的话，它会开一个 pull request，把仓库加进 `data/sources.json`。编辑 issue 会重新触发。
5. 维护者合并 pull request 后，插件会在下次部署时出现在插件市场里。

你也可以在本地完成，然后自己开 pull request：

```bash
bun scripts/marketplace.ts scan owner/repo   # 打印报告（有错误时退出码为 1）
bun scripts/marketplace.ts add owner/repo    # 扫描，然后加进 data/sources.json
```

设置 `GITHUB_TOKEN`（比如 `GITHUB_TOKEN=$(gh auth token)`）后，GitHub API 的额度从每小时 60 次提高到 5000 次。

## 一个仓库放多个插件 [#many-plugins-in-one-repo]

不需要任何额外操作。扫描器会找出仓库里的每个 `PLUGIN.md`，每个都有自己的标识 `owner/repo/<folder>` 和安装链接。大型 monorepo 可以在根目录加一个 `pku-harness.json`，列出插件所在的文件夹。这样扫描更快、顺序固定，示例或测试用的清单也不会混进来：

```json title="pku-harness.json"
{ "plugins": ["services/canteen", "services/library-seat", "services/bus"] }
```

## 更新 [#updating]

直接 push 就行。插件市场大约每小时从默认分支重新扫描一次已上架的仓库，App 也会从链接重新拉取已安装的 `PLUGIN.md` 插件。声明没变的话，更新静默生效；声明变多了（新的校园服务、主机、宿主能力，或者某个工具的效果更强了），更新会等用户同意后才生效。新增插件文件夹就会上架，删掉就会下架。请保持 `id` 不变：用户的安装、小组件和定时检查都靠它来引用插件。

如果某次 push 引入了错误，只有出错的那个插件会被撤下。仓库页面会显示扫描出的问题，方便你修复。

## 下架 [#removal]

- **你自己下架：** 删除 `PLUGIN.md` 文件（或删除仓库、把仓库设为私有）。下次重新扫描时插件就会消失。如果想把仓库条目也删掉，开一个 pull request，从 `data/sources.json` 里移除它。
- **维护者下架：** 违反[审核规则](/docs/marketplace/review)的插件，会通过从 `data/sources.json` 里删除仓库来下架，作者可能会被禁止再次提交。
