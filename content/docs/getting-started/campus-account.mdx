PKU Harness 登录校园服务的方式和浏览器一样，只不过它跑在你的手机上，替你完成这些步骤。它先用 IAAA（统一身份认证）登录一次，再分别登录各个服务：门户、校园卡、树洞、教学网等等。你只需要输入一次账号密码，在“设置 → 校园账号”里，或者在首次启动的引导中。

## 登录时发生了什么 [#what-happens-when-you-sign-in]

1. App 获取 IAAA 的 RSA 公钥，加密你的密码，然后提交登录请求。这部分逻辑移植自 [`pkucli`](https://github.com/pkuinfo/pkucli) 的 `crates/common`。
2. 账号或密码错误时，你会看到 IAAA 返回的提示，App 不会保存任何东西。
3. 登录成功后，学号和密码保存在**设备密钥库**（Expo SecureStore）里。它们不会发送到本项目运行的任何服务器，也不会交给任何插件。
4. 各个校园服务**按需登录**：某个插件第一次用到它时才登录。服务的会话（cookie 或令牌）缓存在手机上，过期后自动刷新。

```
IAAA (iaaa.pku.edu.cn) ──token──► service SSO callback ──► session cached on the device
                                    (portal, card, treehole, blackboard, ITS, cwfw, bdkj, elective, library…)
```

## 二次验证 [#second-factors]

IAAA 通常只要密码，但任何一次登录都可能要求额外验证，包括后台刷新会话的时候。这时 App 会弹出提示，登录流程会等你处理：

| 方式 | 你需要做什么 |
| --- | --- |
| 短信验证码 | 输入发到手机上的验证码。在 Android 上，App 可以提供**一键读取**（SMS User Consent）：你只授权它读取这一条短信，别的都读不到。 |
| 邮箱验证码 | 输入发到邮箱里的验证码。 |
| 手机令牌（OTP） | 如果你在 App 里绑定了身份验证器（见下文），会自动填写；否则从你的令牌 App 里抄过来。 |

有些服务在 IAAA 之外还有自己的验证。树洞会不定期要求短信验证，课程数据还需要单独的令牌。树洞插件会把这些做成一个验证步骤，显示在对话里或它自己的页面上。你在那里完成验证；把验证码告诉助手，它也能替你完成。

### 绑定身份验证器（可选） [#bind-the-authenticator-optional]

内置的**身份验证器**（Authenticator）插件可以把 IAAA 的手机令牌绑定到 App。它先用你保存的账号密码验证身份，IAAA 发来一条绑定短信，你确认验证码即可。之后 App 会自己填写 OTP（比如登录财务系统时），看板上还有一个小组件显示当前的验证码。密钥一直留在密钥库里，插件只能读到当前验证码，读不到密钥本身。

## 校园网 [#the-campus-network]

有些服务只在北大校园网内才能访问，比如财务系统（`cwfw`）。需要它们的插件会声明 `campus-network` [能力需求](/docs/concepts/capabilities)。App 的校园 HTTP 客户端始终**直连**，不走系统代理和 VPN。使用这类插件时，请连校园 Wi-Fi，或者使用能接管整台设备流量的校园 VPN。

<Callout type="warn" title="开发机上开了系统代理">
  如果你的电脑运行着 Clash 之类的代理，启动 Android 模拟器时**不要**继承 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量，否则模拟器无法直连校园服务。
</Callout>

## 退出登录 [#signing-out]

在“设置 → 校园账号”里退出登录，会从手机上删除保存的账号密码和所有缓存的服务会话。“设置 → 数据 → 重置”会清除 App 存储的全部内容。
