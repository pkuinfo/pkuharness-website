PKU Harness 登录校园服务的方式和浏览器相同。区别在于，它在你的手机上运行，替你完成这些步骤。

登录分两层。App 先登录学校的统一身份认证系统 IAAA，然后再分别登录各个服务，例如门户、校园卡、树洞和教学网。你只需要输入一次学号和密码，可以在首次启动的引导中输入，也可以在「设置 → 校园账号」里输入。

## 登录时发生了什么 [#what-happens-when-you-sign-in]

1. App 获取 IAAA 的 RSA 公钥，用它加密你的密码，然后提交登录请求。这部分逻辑移植自 [`pkucli`](https://github.com/pkuinfo/pkucli) 的 `crates/common`。
2. 如果学号或密码错误，你会看到 IAAA 返回的提示，App 不会保存任何内容。
3. 如果登录成功，学号和密码会保存在手机的**密钥库**（Expo SecureStore）里。它们不会发送到本项目运行的任何服务器，也不会交给任何插件。
4. 各个校园服务**按需登录**。也就是说，某个插件第一次用到一个服务时，App 才登录这个服务。服务的会话（cookie 或令牌）缓存在手机上，过期后自动刷新。

下图是这个过程。IAAA 发放一个令牌，App 用它完成目标服务的单点登录（SSO），再把得到的会话保存在手机上。

```
IAAA（iaaa.pku.edu.cn）──令牌──► 服务的 SSO 回调 ──► 会话缓存在手机上
                                  （门户、校园卡、树洞、教学网、ITS、cwfw、bdkj、选课、图书馆等）
```

## 二次验证 [#second-factors]

IAAA 通常只需要密码。但任何一次登录都可能要求额外验证，后台自动刷新会话时也可能。遇到这种情况，App 会弹出提示，登录流程会暂停，等你完成验证。

验证有三种方式。

- **短信验证码**：输入发到你手机上的验证码。在 Android 上，App 可以提供**一键读取**，它用的是系统的 SMS User Consent 接口。你只授权 App 读取这一条短信，其他短信它都读不到。
- **邮箱验证码**：输入发到你邮箱里的验证码。
- **手机令牌**：一种一次性密码（OTP）。如果你在 App 里绑定了身份验证器（见下一节），App 会自动填写。否则，请从你的令牌 App 里抄写验证码。

有些服务在 IAAA 之外还有自己的验证。例如，树洞会不定期要求短信验证，读取课程数据还需要另一个令牌。树洞插件会把这些做成一个验证步骤，显示在对话里或插件自己的页面上。你可以在那里完成验证，也可以把验证码告诉助手，让它替你完成。

### 绑定身份验证器（可选） [#bind-the-authenticator-optional]

App 内置一个**身份验证器**（Authenticator）插件，可以把 IAAA 的手机令牌绑定到 App 上。绑定时，插件先用你保存的学号和密码验证身份，IAAA 随后发来一条绑定短信，你确认其中的验证码即可。

绑定之后，App 会自己填写需要的一次性密码，例如登录财务系统的时候。看板上还有一个小组件显示当前的验证码。令牌的密钥一直保存在密钥库里。插件只能读到当前的验证码，读不到密钥本身。

## 校园网 [#the-campus-network]

有些服务只能在北大校园网内访问，例如财务系统 `cwfw`。需要这类服务的插件会声明 `campus-network` 这项[能力需求](/docs/concepts/capabilities)。

App 发送校园请求时始终**直连**，不经过系统代理或 VPN。所以使用这类插件时，请连接校园 Wi-Fi，或者使用接管整台手机流量的校园 VPN。

<Callout type="warn" title="开发机上开了系统代理">
  如果你的电脑运行着 Clash 之类的代理，启动 Android 模拟器时**不要**继承 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量。否则模拟器无法直连校园服务。
</Callout>

## 退出登录 [#signing-out]

在「设置 → 校园账号」里退出登录，App 会从手机上删除保存的学号、密码和所有缓存的服务会话。「设置 → 数据 → 重置」会清除 App 存储的全部内容。
