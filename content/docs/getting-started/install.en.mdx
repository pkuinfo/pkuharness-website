PKU Harness runs on **Android** today. The iOS version is being prepared. The app already starts
on iOS, but the native HTTP module that makes campus requests has not been ported to Swift yet.
Until it is, you can only sign in to your campus account on Android.

## Download

The latest APK is on the [download page](/en/download), which points to the latest release of
[`pkuinfo/pku-harness`](https://github.com/pkuinfo/pku-harness/releases). Your phone needs an
arm64 processor and Android 7.0 or later.

Install it like any other APK. When Android asks whether your browser may install apps, allow it.

## Checking that you have the official build [#verify-the-build]

Every release APK is built automatically by GitHub Actions from a tagged commit, and every one is
signed with the same key. The release notes list the fingerprints of the APK and of the signing
certificate. You can compare them with the file you installed.

After installation, fixes to the JavaScript code arrive as signed over-the-air (OTA) updates.
They take effect the next time you open the app. Changes to native code still need a new APK.

<Callout type="warn" title="Only install builds you trust">
  The app keeps your campus password in the phone's keystore. Install release builds from the
  official repository, or build the app from source yourself.
</Callout>

## First run

The first time you open the app, it guides you through five steps. You can leave at any point.
The next time you open the app, it continues from the step where you stopped.

<Steps>
<Step>

### Accept the terms

Once you accept, the agent may use plugins for you without asking each time. Later you can require
a confirmation for a particular plugin or kind of action. See
[Permissions](/en/docs/concepts/permissions).

</Step>
<Step>

### Connect an AI model

DeepSeek is the default. Any endpoint that follows the OpenAI API format also works. See
[Connect a model](/en/docs/getting-started/ai-model).

</Step>
<Step>

### Sign in with your campus account

Enter your student ID and password. The app checks them with IAAA, the university's central login
system. See [Campus account](/en/docs/getting-started/campus-account).

</Step>
<Step>

### Pick plugins

Choose which bundled plugins to turn on. You can change this at any time in Settings → Plugins.

</Step>
<Step>

### Allow on-time reminders

Grant the notification and exact-alarm permissions. You can also exempt the app from battery
optimisation. With these, reminders and scheduled checks fire on the minute.

You can skip this step. If you do, the Schedule tab shows which permissions are still missing.

</Step>
</Steps>

## The four tabs

The app has four tabs along the bottom of the screen.

| Tab | Use | Provided by |
| --- | --- | --- |
| **Chat** | Talk to the agent | The app |
| **Dashboard** | See key numbers such as balances and classes | The `dashboard` plugin |
| **Schedule** | Timetable, to-dos and reminders | The `schedule` plugin |
| **Settings** | Account, plugins and preferences | The app |

The **Chat** tab is where the agent lives. Its answers appear as they are written. It can call
plugin tools, and it can show native UI such as forms, pickers and cards inside the conversation.
You can keep several conversations, use commands that start with `/`, and send attachments.

The **Dashboard** tab is a set of widgets, such as your campus-card balance, your next class and
how crowded the canteens are. The agent builds and edits these widgets when you ask, and they
refresh on their own.

The **Schedule** tab shows your timetable, to-dos and reminders. You can describe how a reminder
repeats in ordinary words, for example "every 3 days, 16 times".

The **Settings** tab holds your campus account, the AI service, plugins and their permissions,
the marketplace, memory, notifications, appearance and data.

## Build from source

Building from source needs JDK 17 and the Android SDK.

```bash
git clone --recurse-submodules https://github.com/pkuinfo/pku-harness.git   # plugins/ is a submodule
cd pku-harness
bun install
bun run android        # dev build on an emulator or device
```

The app's `README.md` and `AGENTS.md` describe the full toolchain. To develop plugins against your
own build, see [Bundled plugin → Run it in the app](/en/docs/build/bundled-plugin#run-it-in-the-app).
