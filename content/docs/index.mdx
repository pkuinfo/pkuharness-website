PKU Harness 是北大同学装一个就够的 App。用校园账号（IAAA 统一身份认证）登录一次，就能用上所有校园系统：课表、校园卡、网费、树洞、教学网、财务、场地预约，以及插件带来的任何服务。App 的核心是一个 AI 助手，它可以替你操作这些系统；它能用的每项功能，你在原生界面里也都点一下就能用到。

## 一切皆插件 [#everything-is-a-plugin]

App 本身只是一个 harness：一个 Agent 循环、一套设计系统，加上一组宿主服务。其余的一切都是**插件**（plugin）：每个校园服务、看板、提醒，甚至模型服务商。所有插件地位平等。随 App 一起发布的插件，和同学自己在服务器上跑的插件，遵循同一套约定，出现在同一个插件列表里，受同样的权限管理。

```
 ┌──────────────── PKU Harness app (the harness) ────────────────┐
 │  Agent loop      Design system (HostUI)     Host services      │
 │      │                  │                 (campus, scheduler,  │
 │      └────── tools ─────┴───── screens ──  widgets, todos, …)  │
 └──────────▲──────────────────────▲──────────────────▲───────────┘
            │                      │                  │
   bundled plugins          remote plugins       PKU Harness Cloud
   (TypeScript, SDK)        (MCP over HTTPS)     (optional backend)
```

由此有两条规则，后面的文档会反复用到：

- **人和 AI 是平等的操作者。** 每项能力都是一个有类型的工具（tool）。你点按钮时，界面调用它；对话里，助手调用它。你能做的事，助手都能做，反过来也一样。
- **凭据不离开手机。** 由框架自己登录校园服务，插件拿到的只是响应结果，永远看不到密码和会话令牌。

## 把文档喂给 AI 助手 [#feeding-these-docs-to-an-agent]

每个页面都有 Markdown 版本，你可以只把需要的上下文交给助手。文档有简体中文（默认，路径 `/docs`）和英文（路径 `/en/docs`）两种语言。

| URL | 内容 |
| --- | --- |
| [`/llms.txt`](/llms.txt) | 两种语言所有页面的索引，每页附一句简介 |
| [`/llms-full.txt`](/llms-full.txt) | 所有英文页面合成一个文件 |
| [`/llms-full.zh.txt`](/llms-full.zh.txt) | 所有中文页面合成一个文件 |
| `/docs/<page>.md` | 单个中文页面，例如 [`/docs/sdk/plugin.md`](/docs/sdk/plugin.md) |
| `/en/docs/<page>.md` | 同一页面的英文版 |
| 带 `Accept: text/markdown` 请求 `/docs/<page>` | 与 `.md` 相同（内容协商） |

每页标题下方有 **Copy Markdown** 和 **Open in…** 按钮。Cloud API 参考页的 Markdown 版本会把接口和数据结构以纯文本列出。

```bash
# 把插件检查清单和 SDK 约定交给 Claude Code
curl -s https://<this-site>/docs/for-agents.md https://<this-site>/docs/sdk/plugin.md > plugin-context.md
```
