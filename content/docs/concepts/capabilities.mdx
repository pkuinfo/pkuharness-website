手机不是工作站。插件没有 shell，也没有用户可见的文件系统，后台运行时间有限，有些校园站点只在校园网内才能访问。插件（plugin）在 `PluginDef.requires`（以及注册表条目的 `requires`）里列出它需要的能力，框架把它和设备实际提供的能力做比较。只要有一项不满足，插件就会对助手隐藏，它的工具调用会被拒绝，设置里会显示原因。

```ts
definePlugin({
  id: 'finance',
  // …
  requires: ['campus-session', 'campus-network'],
});
```

## 能力列表 [#the-capabilities]

| 能力 | 含义 | 目前是否提供 |
| --- | --- | --- |
| `network` | 普通的互联网访问（直接 `fetch`） | 是 |
| `campus-network` | 只能在北大校园网内访问的站点 | 声明为可用；不在校园网时请求会失败 |
| `campus-session` | 通过宿主发起的、已登录的校园 HTTP 请求（`services.campus`）；账号密码不会暴露给插件 | Android（依赖原生 campus-http 模块；iOS 要等它的 Swift 移植完成） |
| `notifications` | 本地通知 | 是 |
| `background` | 周期性后台运行 | 是 |
| `cloud` | 已配置 [PKU Harness Cloud](/docs/cloud) 服务商 | 用户配置了服务商期间提供（随配置实时变化） |
| `ongoing` | 常驻通知 / 前台服务（`services.ongoing`） | Android |
| `shell` | shell | 手机上**永远没有**。需要它的插件只能做成远程插件。 |
| `filesystem` | 文件系统 | 不向插件开放。需要用户选择的文件请用 `services.files.pick`。 |

## 规则 [#rules]

- **必须**列出插件的工具依赖的每一项能力。调用 `services.campus.request` 的插件需要 `campus-session`；如果还访问只在校园网内可用的站点，还需要 `campus-network`。
- 内置插件**不得**要求 `shell` 或 `filesystem`。繁重的工作（抓取大量页面、OCR、长时间任务）应该放到远程插件里。
- 远程插件运行在服务器上，所以 `shell` 对它们来说不是设备需求。注册表校验器会拒绝远程条目里的 `requires: ['shell']`。
- **应当**在使用可选服务前先检查：没有 `ongoing` 能力时 `services.ongoing` 为 `undefined`；宿主不支持云服务时 `ctx.cloud` 为 `undefined`。
- 不依赖云也能工作的插件，应声明 `cloud.optional: true`，而不是要求 `cloud`，并检查 `ctx.cloud?.available`。
