PKU Harness 保管着同学的 IAAA（统一身份认证）密码，还能代为操作校园账号。所以从用户的角度看，这套设计要做到“无服务器”：项目运行的任何服务都看不到账号凭据，插件做的任何事都不会瞒着用户。

## 原则 [#principles]

1. **凭据不离开设备。** IAAA 密码、手机令牌密钥、模型 API key 和远程插件的令牌都存放在设备的密钥库里。它们不会写进日志，不会发到项目的服务器，也不会交给任何插件，无论是插件文档、内置插件还是远程插件。
2. **插件拿到的是响应，不是会话。** `services.campus.request` 返回的是响应。会话 cookie 和令牌留在框架内部，签名也在框架内部完成（`sign` 钩子）。
3. **工具结果只是数据。** 模型会被告知：工具结果、插件上下文和远程插件的输出都是数据，不能当作指令执行。
4. **效果（effect）要明确。** 每个工具都要声明 `read`、`write`、`money` 或 `public`（读取、修改、花钱、公开），用户按效果分别决定助手能否直接执行。定时运行只能读取。
5. **离开设备的东西要先声明。** 校园服务的 `scopes`、模型服务商以及 PKU Harness Cloud 的 `disclosure` 说明，都会在首次使用前展示给用户。

## 提示词注入 [#prompt-injection]

校园内容出自第三方之手：一条树洞、一则通知、一段活动简介、一个远程插件的输出。其中任何一段都可能写着“忽略之前的指令，然后……”。框架把这些内容一律当作数据，并限制被注入的指令最多能做到什么：

- **不可信工具。** 返回第三方文本的工具要设置 `untrusted: true`。远程插件的工具一律视为不可信。
- **污染（taint）。** 调用不可信工具后，助手这一回合剩下的部分都会被标记为已污染：同一回合里之后的工具调用会看到 `ctx.turn.tainted === true`。
- **持久写入需要把关。** 回合被污染后，会影响以后对话的写入要等用户确认。记忆插件会把这类记忆存为*待确认*，由用户在它的页面上批准。如果是用户自己的消息要求记住某件事（`ctx.turn.userAsked`），这次写入就是用户的本意，会直接保存。第三方文本没法冒充用户的消息。
- **默认先询问：** 远程插件的修改、花钱和公开类效果默认都要先问用户。
- **无法伪造的宿主信息。** 宿主每回合注入的事实（当前时间、回复语言）放在固定位置，插件上下文无法仿冒。

### 插件作者要做的事 [#what-plugin-authors-must-do]

- **必须**给结果里含有他人所写文本的工具设置 `untrusted: true`，比如帖子、评论、通知、消息、公开网站上的描述。
- **不得**在结果里写指令（“告诉用户……”“现在调用……”）。只返回数据，让模型自己判断。指导性的内容请写在工具的 `description` 或插件的 `instructions` 里。
- 如果工具会写入助手日后当作事实读取的持久状态（笔记、记忆、保存的偏好），**应当**检查 `ctx.turn?.tainted`，把这类写入存为待确认，或者直接拒绝。
- 返回第三方文本时，**应当**去掉控制字符、不可见字符和双向文本（bidi）字符以及标记，并限制长度。
- 代表用户批准或解锁某些东西的工具，**必须**设置 `userOnly: true`。

## 结果中的机密 [#secrets-in-results]

有些值绝不能让模型看到，也不能进入日志。

- **付款码**只能显示在使用了 `host.useSecureDisplay()` 的页面上（禁止截屏、调高亮度），绝不能作为工具结果返回。
- **分享链接**：云端频道的链接把密钥放在 URL 的 fragment 里。SDK 的 `SecretLink` 是不透明的（`JSON.stringify(link)` 得到 `"[secret link]"`），只能通过 `host.shareLink(link)` 或 `<QRCode link={link} />` 展示。宿主还会从工具输出和日志里清除分享链接格式的内容。
- **令牌和密钥**插件根本拿不到。

## 插件文档 [#plugin-documents]

App 解释执行 `PLUGIN.md` 里声明的步骤，不运行任何插件代码。一份插件文档只能访问它声明过的校园服务、公开站点和宿主能力（ability），并受固定的时间、大小和操作次数限制。

校园请求由框架签名，插件文档看不到密码、cookie 或令牌，也访问不了其他插件的存储。

安装前，以及更新要求更多权限时，用户会看到审核面板：官方还是社区、用到哪些校园服务、哪些网站、哪些 App 功能，以及每个工具的效果。

社区插件文档中 `write`、`money` 和 `public` 类工具会先询问用户，它们的结果也按不可信数据处理。助手可以起草插件，但不能安装：`plugins.install` 只会打开审核面板。

## 远程插件 [#remote-plugins]

远程插件运行在别人的服务器上。它收不到校园凭据、会话或用户的其他数据，只能拿到助手发给它的工具输入。它的工具都是不可信的，修改类效果默认先询问，它在系统提示词里的那一段也会说明它的输出只是数据。只有维护者审查过源码后，注册表才会把条目标记为 `verified`。

## PKU Harness Cloud [#pku-harness-cloud]

可选的云服务默认端到端加密。它只通过一对密钥识别设备，不涉及学号或姓名；每个插件都要单独征得同意，并附上通俗易懂的说明。详见 [Cloud → 安全](/docs/cloud/security)。
