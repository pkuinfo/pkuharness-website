PKU Harness is an Android app that helps Peking University students with campus services. You
sign in once with your campus account, and the app gives you your timetable, campus card,
network fee, Treehole (树洞), Blackboard (教学网), finance, room booking and other campus
systems. Sign-in goes through IAAA, the university's central login system. Plugins can add
more services.

At the centre of the app is an AI assistant, which we also call the agent. You describe what you
need in a conversation, and the agent works the campus systems for you. Every feature the agent
can use also has a button in the app's native screens, so you can do the same thing yourself.

## How the app and its plugins fit together [#everything-is-a-plugin]

The app itself provides only the basic machinery. It has an agent loop, which is the program that
lets the AI think, call tools and answer. It also has a design system for screens and a set of
host services, such as campus sign-in, scheduled tasks, widgets and to-dos. We call this layer
the _harness_.

Everything else comes from **plugins**. Each campus service is a plugin, and so are the
dashboard, reminders and even the AI model provider. A plugin that ships inside the app and a
plugin that a student runs on their own server use the same interface. Both appear in the same
plugin list and use the same permission system.

This design leads to two rules that the rest of these docs come back to often.

- **You and the agent can do exactly the same things.** Each feature is one typed _tool_. When
  you tap a button, the screen calls the tool. When you ask in a conversation, the agent calls
  the same tool.
- **Credentials never leave the phone.** The harness signs in to campus services itself. Plugins
  receive only the responses, and never see your password or session tokens.

## Giving these docs to an AI agent [#feeding-these-docs-to-an-agent]

Every page is also available as Markdown. This lets you give an AI agent only the pages it needs
instead of the whole site. The docs are written in Simplified Chinese and English. Chinese is the
default and lives under `/docs`. English lives under `/en/docs`.

| URL | Content |
| --- | --- |
| [`/llms.txt`](/llms.txt) | Index of every page in both languages, with one-line descriptions |
| [`/llms-full.txt`](/llms-full.txt) | Every English page in one file |
| [`/llms-full.zh.txt`](/llms-full.zh.txt) | Every Chinese page in one file |
| `/en/docs/<page>.md` | One English page, for example [`/en/docs/sdk/plugin.md`](/en/docs/sdk/plugin.md) |
| `/docs/<page>.md` | The same page in Chinese |
| `/en/docs/<page>` with the header `Accept: text/markdown` | Same as `.md` |

The last row uses HTTP content negotiation: the server reads the request header and returns
Markdown instead of HTML.

Under each page title there are two buttons, **Copy Markdown** and **Open in…**. In the Markdown
version, the Cloud API reference pages list their operations and schemas as plain text.

```bash
# Give Claude Code the plugin checklist and the SDK contract
curl -s https://<this-site>/en/docs/for-agents.md https://<this-site>/en/docs/sdk/plugin.md > plugin-context.md
```
