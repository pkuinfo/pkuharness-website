## 选择服务商（用户） [#choosing-a-provider-users]

「设置 → 云服务」提供三个选项：

| 选项 | 含义 |
| --- | --- |
| **官方** | 由 pkuinfo 运营的实例（尚未上线）。它保持精简：只有实时分享用的中继、小容量的端到端加密存储和查看页。用户主动开启前默认关闭。 |
| **自建** | 填一个基础 URL。点**测试连接**会显示该服务商 `/v1/meta` 返回的运营者、服务和限额。 |
| **关闭** | 不使用云服务。必须用云服务的插件不可用；云服务可选的插件照常在本地工作。 |

URL 必须是 HTTPS。开发版额外允许 `http://10.0.2.2:*`、`http://localhost:*` 和 `http://127.0.0.1:*`。切换服务商不会迁移数据：每家服务商都是独立的身份和存储。

## 服务商需要实现什么 [#what-a-provider-implements]

[API 参考](/docs/cloud/api/meta)里的全部内容，并用 [`@pku-harness/cloud-protocol`](/docs/cloud/protocol-package) 的 schema 做校验：

- `GET /v1/meta`，返回 `protocol: 1`、提供的服务、限额、工作量证明参数、查看页、函数和运营者信息（`name`、`contact`，可选 `privacyURL`）。
- 带工作量证明的设备注册，以及签名换取 token（`aud` 为你自己的源，允许 5 分钟时钟偏差，防 nonce 重放），token 有效期 10 分钟。
- 你在 `services` 里列出的服务。服务商可以只提供其中一部分；`uses` 没被覆盖的插件会被标为不可用。
- 错误响应体 `{ error: { code, message, retryAfterS? } }`，以及 `Retry-After` 和 `RateLimit-*` 响应头。
- `/w/<plugin>/<page>` 下带严格 CSP 的静态查看页，以及 `GET /s/:id` 重定向。

## 参考服务器 [#reference-server]

开源参考服务器位于 [`pku-harness-plugins`](https://github.com/pkuinfo/pku-harness-plugins/tree/main/packages/cloud-server) 的 `packages/cloud-server`。它基于 Bun + Hono + `bun:sqlite`（WAL），每个请求和响应都用 `@pku-harness/cloud-protocol` 的 schema 校验。它声明提供 `store`、`channels` 和 `functions`；`push` 返回 `501 unsupported`。插件服务端函数（`/v1/fn`、`/v1/p`）受 `CLOUD_FN_POLICY` 控制，生产环境（`NODE_ENV=production`）默认是空列表的 `allowlist`，官方服务器目前也不开启。

```bash
cd pku-harness-plugins/packages/cloud-server
bun run dev        # http://localhost:8787，改动后自动重载，数据在 ./data/cloud.db
bun test           # 路由测试 + 真实的 WebSocket/SSE 测试
# 或者在仓库根目录：bun run --filter @pku-harness/cloud-server dev
```

在 Android 模拟器里，把「设置 → 云服务 → 自建」指向 `http://10.0.2.2:8787`。

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `PORT` / `HOST` | `8787` / `0.0.0.0` | 监听地址 |
| `CLOUD_PUBLIC_URL` | `http://localhost:$PORT` | 客户端访问用的源，也是 token 挑战里的 `aud` |
| `CLOUD_DB` | `./data/cloud.db` | SQLite 文件（临时跑一下可以用 `:memory:`） |
| `CLOUD_TOKEN_SECRET` | 自动生成并存进数据库 | bearer token 的 HMAC 密钥（至少 32 个字符） |
| `CLOUD_POW_DIFFICULTY` | `16` | 工作量证明难度 |
| `CLOUD_POW_ROTATE_S` | `21600` | salt 轮换周期；上一个 salt 会再多有效一个周期 |
| `CLOUD_OPERATOR_NAME` / `CLOUD_OPERATOR_CONTACT` / `CLOUD_PRIVACY_URL` | `PKU Harness Cloud (self-hosted)` / 空 | 由 `GET /v1/meta` 返回 |
| `CLOUD_PAGES_DIR` | `<plugins repo>/plugins` | 存放 `<plugin>/web/dist` 查看页的目录 |
| `CLOUD_TRUST_PROXY` | 关闭 | 设为 `1` 时，客户端 IP 取 `X-Forwarded-For` 的最后一跳（部署在 Caddy 后面时用） |

`deploy/` 里有 Dockerfile、Caddyfile 和 Litestream 配置，说明见其中的 `README.md`。服务端函数相关的变量（`CLOUD_FN_POLICY`、`CLOUD_FN_ALLOW`、`CLOUD_FN_VERIFIED`、`CLOUD_FN_LOCAL`、`CLOUD_SECRET_<PLUGIN>__<NAME>`）写在服务器自己的 `README.md` 里。

## 运营一个实例 [#operating-an-instance]

- 公开你是谁（`operator.name`、`contact`），并发布隐私声明（`privacyURL`）。
- 日志里不要记录数据内容和 token。数据虽然是密文，但 IP 地址和时间同样属于个人信息。
- 在中国大陆托管需要 ICP 备案。官方实例计划部署在大陆以外，并为分享链接准备一个专用短域名。微信可能会对陌生域名弹出拦截提示，所以 App 总是同时提供二维码和复制链接。
