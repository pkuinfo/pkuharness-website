## 1. Declare it

```ts
import { definePlugin } from '@pku-harness/sdk';

export const cardSharePlugin = definePlugin({
  id: 'card-share',
  name: '付款码共享',
  description: '把校园卡付款码实时分享给朋友，端到端加密。',
  version: '0.1.0',
  requires: ['campus-session', 'network', 'cloud'],
  cloud: {
    protocol: 1,
    uses: ['channels'],
    e2e: true,
    pages: ['view'],
    disclosure: {
      zh: ['分享期间，加密后的付款码经云服务转发给你分享的人；服务器无法解密', '服务器能看到：分享的开始/结束时间、查看者的 IP'],
      en: ['While sharing, encrypted payment codes are relayed to the person you shared with; the server can’t decrypt them', 'The server sees when a share starts and ends, and the viewer’s IP address'],
    },
  },
  defaultModes: { read: 'auto', write: 'auto', money: 'ask' },
  scopes: ['bdcard.pku.edu.cn'],
  tools: { /* … */ },
});
```

| Field | Rule |
| --- | --- |
| `protocol` | `1` |
| `uses` | Only the services you call. The host refuses calls to any other. |
| `disclosure.zh` | **Required** when `uses` isn't empty. In plain words, say exactly what leaves the device and what the server can see, one fact per line. If you add `en`, it must translate every line. |
| `e2e` | `true` makes the host refuse plaintext store writes. Set it whenever you can. |
| `optional` | `true` if the plugin also works without the cloud. Then don't list `'cloud'` in `requires`, and check `ctx.cloud?.available`. |
| `pages` | Static viewer pages from `plugins/<id>/web`, served at `/w/<plugin>/<page>` for people without the app. |
| `functions`, `backend` | Server functions, or an external backend URL (shown to the user before consent). Server functions are off on the official server for now; see [below](#server-functions). |

## 2. Consent

Every plugin needs the user's consent. The plugin's page in Settings has a **Cloud** section
showing the provider host, your disclosure lines, an E2E badge, the services used and usage
against quota, plus an **Allow cloud** switch and a **Clear this plugin's cloud data** button.

Until the user allows it, every call throws `CloudError('consent_required')`. In a screen, ask
first with `cloud.requestConsent()`: it shows the host's consent sheet and resolves `true` (right
away if the user already allowed it) or `false` if they decline. Agent tool calls never prompt.
Let the error through, and the agent tells the user where to allow it.

```tsx
const start = async () => {
  if (!(await props.cloud?.requestConsent())) return; // declined, or no cloud on this host
  const channel = await props.cloud!.channels.open({ ttlS: 30 * 60, maxPeers: 1, page: 'view' });
  // …
};
```

```ts
import { isCloudError } from '@pku-harness/sdk';

try {
  await ctx.cloud?.store.put('prefs', prefs);
} catch (e) {
  if (isCloudError(e, 'consent_required')) return { status: 'cloud_consent_required' };
  if (isCloudError(e, 'offline')) throw new Error('网络不可用，稍后再试');
  throw e;
}
```

## 3. Availability

```ts
const cloud = ctx.cloud;
if (!cloud?.available) {
  // provider not configured, no consent, or unreachable
  return { status: 'cloud_unavailable', provider: cloud?.status().provider ?? 'off' };
}
```

`status()` returns `{ provider: 'official' | 'custom' | 'off', baseURL?, consented, online }`.
When the phone is offline, store reads fall back to a local mirror, while writes and function
calls fail fast with `offline` (there is no silent outbox). Channels reconnect with backoff.

## 4. Store

```ts
const cur = await ctx.cloud!.store.get<{ count: number }>('counter');
await ctx.cloud!.store.put('counter', { count: (cur?.value.count ?? 0) + 1 }, { ifVersion: cur?.version ?? 0 });
const keys = await ctx.cloud!.store.list('history/');
```

- The provider namespaces keys to `(device, plugin)`, so no other plugin can read them.
- `ifVersion` gives you optimistic concurrency (`0` means the key must not exist yet). On a
  mismatch the server answers `409 conflict`, which the host throws as `CloudError('protocol')`.
- `ttlS` makes a value expire. Default quotas: 1 MB and 1,000 keys per plugin per device, 64 KB
  per value.

## 5. Channels

A channel relays end-to-end encrypted frames between the owner's phone and the people who open a
share link. The provider forwards ciphertext and gates who may join; only link holders can
decrypt.

```ts
const channel = await cloud.channels.open({
  ttlS: 30 * 60,          // required, 60 s – 24 h
  maxPeers: 1,            // first joiner claims the seat; a forwarded link is useless
  page: 'view',           // viewer page for people without the app
  meta: { nameHint: '王_明', pinRequired: true },  // sealed; viewers read it before joining
});

const off = channel.on('message', (e) => {
  if (e.type !== 'message') return;
  const msg = frameSchema.safeParse(e.msg);  // always validate peer frames
  if (!msg.success) return;
  // …
});
channel.on('join', (e) => e.type === 'join' && void channel.send(e.peerId, { t: 'hello' }));

// later
await channel.extend(15 * 60);
await channel.close();
off();
```

- `send(peerId | '*', msg)` seals the message for each peer. Frames are at most 4 KB, at most 60
  per minute.
- `mailbox.put(slot, msg, ttlS)` leaves sealed blobs that peers can read while you're offline.
- `kick(peerId)` drops a viewer and frees the seat; the same link then works for a new viewer.
- `channels.get(id)` and `list()` survive app restarts, because the keys live in the keystore.
- For long shares on Android, keep the app alive with
  `services.ongoing.start({ title, until, onStop })`. `services.ongoing` exists only on Android.

### Showing the link

`channel.link` is a `SecretLink`. You can't read the URL, and it serialises as `"[secret link]"`.

```tsx
const { QRCode, Button } = host.components;
<QRCode link={channel.link} size={220} />
<Button title="分享给朋友" onPress={() => void host.shareLink?.(channel.link, { message: '我的付款码' })} />
```

You **must not** return links from tools or write them to logs. A tool returns
`{ status: 'awaiting_user' }` and opens a screen instead.

## 6. Registry entry

Copy the cloud declaration into your `registry.json` entry, so the marketplace shows "uses cloud"
before anyone installs the plugin:

```json
{
  "id": "card-share",
  "cloud": {
    "uses": ["channels"],
    "e2e": true,
    "disclosure": { "zh": ["分享期间，加密后的付款码经云服务转发给你分享的人；服务器无法解密", "服务器能看到：分享的开始/结束时间、查看者的 IP"] }
  }
}
```

The registry validator checks that `disclosure.zh` is there when `uses` isn't empty, that `en`
(if given) translates every line, and that an external `backend.url` uses HTTPS.

## Server functions

<Callout type="warn" title="Off on the official server for now">
  Keep your plugin on the phone, or run your own backend.
</Callout>

A `PLUGIN.md` plugin declares server functions in a `server:` section (with the same steps and
expressions as its tools) and calls them through the `cloud.call { fn, input }` ability. Widgets
can bind `{ fn }`. The section implies `uses: [functions]` and requires `disclosure`. The
reference server runs `access: user` functions at `POST /v1/fn/<plugin>/<name>` and
`access: public` ones at `/v1/p/<plugin>/<name>`, with server KV, crypto and HTTPS to the
declared hosts. See [Cloud → Server functions](/en/docs/cloud#server-functions) and
[`docs/CLOUD-FUNCTIONS.md`](https://github.com/pkuinfo/pku-harness/blob/master/docs/CLOUD-FUNCTIONS.md)
(on hold).

## Viewer pages

People without the app open `https://<provider>/s/<id>#k=…`, which redirects to
`/w/<plugin>/<page>?c=<id>#k=…` (the fragment survives the redirect). Build the page in
`plugins/<id>/web` as a static site (Vite + Preact, for example), read `k` from `location.hash`,
and use [`@pku-harness/cloud-protocol`](/en/docs/cloud/protocol-package) to derive the keys, join
and decrypt. Pages have to work in the WeChat webview, so don't depend on WebCrypto (the package
uses pure-JS noble crypto) and fall back to SSE when WebSockets aren't available.
`plugins/card-share/web` is a complete viewer to copy from.
